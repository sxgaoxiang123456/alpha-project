## 1. 功能概述 *(mandatory)*

### 1.1 What

F7 AI 早盘简报是一个在**每个交易日开盘前**自动生成的市场概览推送。它基于前一交易日收盘数据、当日早盘数据（如有）以及用户自选股/预警历史，通过大语言模型生成自然语言解读，并以结构化卡片形式推送给用户。

简报内容包含三个核心模块：

- **大盘概览**：上证指数、深证成指、创业板指等主要指数的点位与涨跌幅
- **异动 TOP 5**：涨速、成交量突增等异常波动的股票及其解读
- **AI 自然语言解读**：由大语言模型对当日市场氛围、板块热点、潜在风险生成的简短分析

### 1.2 Why

根据 PRD §2.2 产品目标与 §3.1 主要画像，上班族散户在开盘前 5 分钟内需要快速掌握市场动态，以降低信息筛选成本。当前 MVP 阶段的简报仅为固定模板（大盘指数 + 空异动列表），无法提供真正的信息价值。AI 早盘简报将验证「低密度信息 + 主动推送」模式是否能有效降低散户的信息焦虑。

### 1.3 MVP 约束

本功能属于 v1.1 阶段，需遵守以下约束：

- 仅服务**单用户**（延续 MVP 单用户架构）
- 仅覆盖 **A 股市场**
- 推送通道复用现有**飞书主通道 + Telegram 备用通道**
- 数据源复用现有 **AkShare / BaoStock 双源容灾**机制
- 不引入付费数据源
- 不做实时流式生成，采用**定时批量生成**模式
- 不提供用户手动编辑简报内容的功能
- 不提供多语言简报

## 2. Clarifications

### Session 2026-06-17

- **Q1**: 异动 TOP 5 的股票池范围？→ **A**: 自选股不为空时优先从自选股中计算，不足 5 只时从全市场补充；自选股为空时从全市场选取。
- **Q2**: 手动刷新是否受「同一分钟内不重复生成」限制？→ **A**: 不受定时任务限制，但手动刷新独立设置 30 秒冷却期。
- **Q3**: 新股/次新股历史行情不足时如何处理？→ **A**: 用可用天数计算均量，标记「数据不足」并降低异动权重。
- **Q4**: LLM API 重试间隔与总超时？→ **A**: 单次调用 30 秒，失败间隔 5 秒重试，总耗时硬上限 60 秒。
- **Q5**: 简报生成与行情刷新并发冲突如何处理？→ **A**: 简报启动前等待行情刷新完成，最多 15 秒，超时后基于缓存独立执行。


### 2.1 触发时机

- **定时触发**：交易日 8:50 自动触发；启动前检查是否有正在执行的行情刷新任务，若有则等待其完成，最多等待 15 秒；目标在 **9:00 前完成推送**（OQ-08 已决策为 9:00）
- **手动触发**：用户可在 Dashboard 点击「重新生成简报」按钮手动触发一次；手动刷新有独立 30 秒冷却期，不受定时任务「同一分钟内不重复生成」限制
- **非交易日**：跳过生成，仅记录日志

### 2.2 数据时间窗口

- **大盘指数**：使用最近一次成功获取的行情数据
- **异动股票**：基于最近 1-5 个交易日的成交量与价格变化计算
- **预警历史**：参考过去 24 小时内触发的预警规则
- **历史行情**：复用 MVP 阶段已落盘的 `HistoricalQuote` 数据（保留 90 天）

### 2.3 推送目标

- 主通道：飞书卡片
- 备用通道：Telegram 文本
- 双通道失败时：本地推送日志记录失败状态，Dashboard 显示未读标记

## 3. 用户场景与验收 *(mandatory)*

### User Story 1 - 交易日自动接收 AI 简报（Priority: P1）

作为上班族散户，我希望在每天开盘前收到 AI 生成的早盘简报，以便在 5 分钟内掌握当日市场动态，无需手动打开行情软件筛选信息。

**Why this priority**：这是 F7 的核心价值主张，直接验证 PRD 的「低密度信息 + 主动推送」假设。

**Independent Test**：在交易日 8:50-9:00 之间，系统能自动生成并推送一条包含大盘指数、异动 TOP 5 和 AI 解读的结构化简报。

**Acceptance Scenarios**：

1. **Given** 当前为交易日且数据源可用，**When** 系统执行 8:50 简报生成任务，**Then** 用户在 9:00 前收到飞书卡片，卡片包含上证指数/深证成指/创业板指数据及至少 3 条异动股票信息
2. **Given** 用户已配置 Telegram 但未配置飞书，**When** 简报生成完成，**Then** 用户通过 Telegram 收到文本版简报
3. **Given** 用户同时配置飞书和 Telegram，**When** 飞书通道可用，**Then** 优先通过飞书发送，Telegram 不重复发送

---

### User Story 2 - LLM 失败时收到降级简报（Priority: P1）

作为用户，当 AI 服务不可用时，我希望仍收到一份基于模板的市场数据简报，而不是错误通知或空白消息。

**Why this priority**：保证功能可用性，避免因第三方 LLM 服务波动导致核心体验完全中断。

**Independent Test**：人为模拟 LLM API 连续失败，系统仍能发送包含大盘指数和异动数据的模板简报。

**Acceptance Scenarios**：

1. **Given** LLM API 连续 3 次调用失败，**When** 系统生成简报，**Then** 降级为纯 Jinja2 模板简报并推送给用户，状态标记为「模板降级」
2. **Given** 降级简报已发送，**When** 用户查看 Dashboard 推送历史，**Then** 能看到该条记录的状态为「sent」且备注含「模板降级」

---

### User Story 3 - 非交易日跳过生成（Priority: P2）

作为系统运维者，我希望非交易日不触发简报生成，以减少不必要的 API 调用和日志噪音。

**Why this priority**：降低运营成本，避免非交易日产生无意义的 LLM 调用费用。

**Independent Test**：将系统日期设为周末或法定节假日，确认简报任务被跳过。

**Acceptance Scenarios**：

1. **Given** 当前日期为非交易日，**When** 到达 8:50 简报任务触发时间，**Then** 不调用 LLM，不发送推送，仅写入一条「非交易日跳过」日志

---

### User Story 4 - 手动刷新简报（Priority: P2）

作为用户，我希望在 Dashboard 上手动触发一次简报生成，以便在错过定时推送或想查看最新解读时立即获得。

**Why this priority**：提供用户可控的补救路径，增强对系统的信任感。

**Independent Test**：在 Dashboard 点击「重新生成」按钮后，用户能在 60 秒内收到新的简报。

**Acceptance Scenarios**：

1. **Given** 用户在 Dashboard 点击「重新生成简报」，**When** 系统完成生成，**Then** 推送新简报并在页面显示「简报已刷新」提示
2. **Given** 用户在非交易日点击「重新生成简报」，**When** 系统校验交易日历，**Then** 提示「今日非交易日，暂无简报」

## 4. 边界条件与异常处理 *(mandatory)*

### 4.1 数据源边界

- **全部数据源不可用**：基于缓存数据生成简报；若缓存也过期，则发送「数据暂不可用」系统通知，不发送误导性市场解读
- **部分股票数据缺失**：缺失股票不纳入异动计算，其他股票正常计算
- **新股/次新股历史行情不足 5 日**：用已有可用天数计算均量，在简报中标记「数据不足」，并降低该股票的异动权重，避免样本不足导致误报
- **自选股为空**：简报仍生成大盘概览部分，异动 TOP 5 取自全市场而非仅自选股
- **自选股不为空**：异动 TOP 5 优先从自选股中计算，若自选股中不足 5 只异动标的，再从全市场补充至 5 只

### 4.2 LLM 边界

- **LLM API 超时**：单次调用超时 30 秒，失败间隔 5 秒重试，总耗时（数据准备 + LLM + 重试）硬上限 60 秒；超时后降级为模板简报
- **LLM 返回格式异常**：无法解析为结构化数据时，使用模板渲染原始文本
- **LLM 返回内容为空**：视为生成失败，触发降级
- **LLM 成本或配额不足**：不影响系统运行，降级为模板简报

### 4.3 推送边界

- **飞书限流或认证失败**：自动降级到 Telegram；双失败则记录本地日志
- **简报内容超长**：截断为摘要 +「查看详情」链接，保留核心大盘与 TOP 3 异动
- **推送通道均未配置**：生成简报但不推送，Dashboard 显示「未配置推送通道」提示

### 4.4 性能边界

- **生成耗时**：从数据准备到推送完成，p95 < 60 秒；其中 LLM 单次调用 30 秒、重试间隔 5 秒、总耗时硬上限 60 秒
- **同时生成次数**：同一分钟内仅允许一次简报生成任务，防止重复触发；手动刷新独立设置 30 秒冷却期
- **手动刷新冷却期**：用户触发手动刷新后，30 秒内再次点击无效，页面提示「简报刷新过于频繁，请稍后再试」
- **简报卡片大小**：飞书卡片内容控制在 4096 字符以内

### 4.5 任务并发边界

- **行情刷新进行中**：简报生成任务启动前检测是否有正在执行的行情刷新任务，若有则等待最多 15 秒；超过 15 秒仍未完成，则基于最新缓存数据独立执行
- **简报生成期间行情刷新触发**：新的行情刷新任务不阻塞简报生成，各自独立执行
- **手动刷新与定时任务并发**：若用户手动刷新时定时任务也在执行，后者因「同一分钟内不重复生成」规则被跳过，避免重复

## 6. 需求 *(mandatory)*

### 6.1 Functional Requirements

- **FR-001**：系统 MUST 在交易日 8:50 自动触发简报生成任务
- **FR-002**：系统 MUST 在生成简报前校验当前日期是否为交易日
- **FR-003**：系统 MUST 从现有数据源获取大盘指数、自选股行情、历史行情作为输入
- **FR-004**：系统 MUST 计算涨速最快 / 成交量突增的 TOP 5 股票；自选股不为空时优先从自选股中选取，不足 5 只时从全市场补充
- **FR-005**：系统 MUST 调用大语言模型生成自然语言市场解读
- **FR-006**：系统 MUST 将 LLM 输出与模板结合，渲染为结构化卡片
- **FR-007**：系统 MUST 通过现有推送通道发送简报
- **FR-008**：系统 MUST 在 LLM 连续 3 次调用失败时降级为纯模板简报
- **FR-009**：系统 MUST 记录每次生成结果到推送日志，包含状态、耗时、是否降级
- **FR-010**：系统 MUST 提供 Dashboard 手动触发入口
- **FR-011**：系统 MUST 在生成耗时超过 60 秒时中断并降级；其中 LLM 单次调用超时 30 秒，失败间隔 5 秒重试
- **FR-012**：系统 MUST 保证同一分钟内不重复生成简报；手动刷新独立设置 30 秒冷却期
- **FR-013**：系统 MUST 在简报生成前检测正在执行的行情刷新任务，等待最多 15 秒，超时后基于最新缓存数据独立执行

### 6.2 Key Entities

- **Briefing（简报）**：一次生成任务的输出，包含日期、大盘指数、异动 TOP 5、AI 解读文本、生成状态
- **Market Snapshot（大盘快照）**：主要指数的当前点位、涨跌幅、成交额
- **Top Mover（异动股票）**：代码、名称、异动类型、数值、所属板块、一句话解读
- **Prompt Template（提示模板）**：用于构造 LLM 输入的结构化模板，包含系统角色、数据输入、输出格式要求
- **Briefing Log（简报日志）**：生成时间、耗时、使用数据源、LLM 状态、推送状态、降级原因

## 7. 验收标准 *(mandatory)*

### 7.1 Measurable Outcomes

- **SC-001**：用户在交易日 9:00 前收到简报推送的比例 > 95%
- **SC-002**：简报生成到推送完成的端到端耗时 p95 < 60 秒
- **SC-003**：简报卡片包含至少 3 条异动股票信息的比例 > 95%
- **SC-004**：LLM 失败时模板降级简报成功推送的比例 > 99%
- **SC-005**：非交易日不产生 LLM API 调用
- **SC-006**：简报生成任务在同一分钟内不重复触发

### 7.2 Acceptance Criteria (Given/When/Then)

**AC-F7-01：正常交易日简报生成**

- **Given** 当前为交易日且 8:50 到达生成时间
- **When** 系统执行简报生成任务
- **Then** 9:00 前用户收到飞书卡片，包含上证指数/深证成指/创业板指 + 至少 3 条异动信息 + AI 解读

**AC-F7-02：LLM 失败降级**

- **Given** LLM API 连续 3 次调用失败
- **When** 系统生成简报
- **Then** 用户收到纯模板简报（大盘指数 + 异动数据，无 AI 解读），状态标记为模板降级

**AC-F7-03：非交易日跳过**

- **Given** 当前日期为非交易日
- **When** 到达 8:50 简报任务时间
- **Then** 不调用 LLM，不发送推送，仅记录「非交易日跳过」日志

**AC-F7-04：手动刷新简报**

- **Given** 用户在 Dashboard 点击「重新生成简报」
- **When** 系统完成生成
- **Then** 60 秒内用户收到新简报，页面显示刷新成功提示

**AC-F7-05：数据源不可用保护**

- **Given** 全部数据源不可用且缓存过期
- **When** 系统尝试生成简报
- **Then** 发送「数据暂不可用」系统通知，不生成误导性市场解读

## 8. 假设与依赖 *(mandatory)*

### 8.1 假设

- 用户已完成飞书或 Telegram 推送通道配置，否则简报仅生成不推送
- 历史行情数据已按 MVP 设计异步落盘并保留 90 天
- LLM API 密钥由用户在环境变量中配置，本功能仅负责调用
- 单用户架构不变，无需按用户隔离简报
- 用户接受 AI 生成内容仅供参考，不构成投资建议

### 8.2 依赖

- 复用 MVP 的 `HistoricalQuote` 模型存储的历史行情数据
- 复用 MVP 的 `AlertTrigger` 模型获取过去 24 小时预警记录
- 复用 MVP 的 `MarketIndexService` 获取大盘指数
- 复用 MVP 的 `PushService` 及飞书/Telegram 客户端发送简报
- 复用 MVP 的 `DataSourceFacade` 获取实时/历史行情
- 复用 MVP 的交易日历判断逻辑

## 9. 功能边界 *(mandatory)*

### 9.1 In Scope

- 交易日定时 AI 简报生成与推送
- 大盘指数展示
- 异动 TOP 5 计算与展示
- LLM 自然语言解读生成
- LLM 失败时的模板降级
- Dashboard 手动刷新入口
- 简报生成日志记录

### 9.2 Out of Scope

- 不提供个股买卖点建议
- 不提供实时盘中简报（仅早盘一次）
- 不提供用户自定义简报模板
- 不提供多语言简报
- 不提供简报历史详情页（仅展示最近一条）
- 不提供社交分享功能
- 不提供 PDF / 图片版简报
- 不接入付费 Level-2 行情数据源
